## 一、全景：一套伺服系统里谁干什么

一句话：**上位机出"意图"，驱动器出"力"的闭环，电机出"转"，编码器出"事实"。**

| 角色 | 是谁 | 干什么 | 对上位机的意义 |
|---|---|---|---|
| 上位机 | PLC / CNC / 运动控制器 / PC 软件 | 发指令（位置/速度/转矩）、收状态、配参数、做多轴协调 | 你要写、要调的那一层 |
| 伺服驱动器（放大器） | MR-J5 等 | 把指令变成精确的电流，位置/速度/转矩闭环在这里闭合 | 调试对象：参数、监视、报警都在它身上 |
| 伺服电机 | HG 系列 | 出转矩 | 与驱动器配套，别跨系列混搭 |
| 编码器 | 电机尾端 26 位 | 报位置/速度/磁极位置 | 闭环的"事实来源"（详见本文第四节与《MR-J5 清单》第五节） |

类比：上位机 = 大脑（决定去哪），驱动器 = 小脑（反射式闭环让动作跟手），电机 = 肌肉，编码器 = 本体感觉。

上位机与驱动器之间至少三条通道（物理上可能合在同一根线里）：

- **指令通道**：告诉驱动器目标（脉冲 / 模拟量 / 总线报文）；
- **状态通道**：驱动器汇报准备好/到位/报警/负载；
- **配置通道**：读写参数、调谐、监视（USB、RS-485、以太网，通常是调试工具在用）。

### 上位机的具体类型

| 类型 | 典型代表 | 到驱动器的通道 | 适合场景 | 调试关注点 |
|---|---|---|---|---|
| PLC | 三菱 R/Q 系列（梯形图/ST），可加 Simple Motion 运动模块（RD77MS 等） | 脉冲、模拟量、总线模块（CC-Link IE TSN / EtherCAT） | 逻辑+顺序控制为主的产线设备 | 网络参数与程序扫描的配合（ST 写法见《CC-Link 通讯详解.md》第十节） |
| CNC 数控装置 | 三菱 M800/M80 等 | SSCNET III/H 光纤总线 | 机床多轴插补 | 插补与 G 代码在 CNC 侧完成，驱动器只管执行；联动调试在 CNC 侧做 |
| 专用运动控制器 / 运动控制卡 | 独立运动控制器、PC + PCI/PCIe 控制卡 | 脉冲、模拟量、EtherCAT | 电子凸轮、飞剪、多轴同步 | 主站固件版本、轴配置与驱动器的映射 |
| PC 自研上位机 | C#/LabVIEW 软件 + Modbus 或总线主站 | Modbus RTU/TCP、EtherCAT 主站、RS-485 | 测试台、实验室、无 PLC 小设备 | 实时性边界（第十节 Modbus 边界表）、第十四节硬规则 |
| 机器人控制器 | 机器人本体控制器 | 内藏专用总线 | 机器人各轴伺服 | 对用户接近黑盒，调试在机器人系统侧做 |

### 常见系统架构：先看懂"这台伺服归谁管"

**架构 A：点位控制（脉冲 / 模拟量）**

```
[PLC / 运动卡] ──脉冲 / ±10V──> [驱动器] ──> [电机]
```

- 每轴一根线、各轴独立；轨迹与逻辑都在控制器侧算；
- 调试最简单，但多轴同步能力差——适合输送、定位这类单轴点位场景。

**架构 B：高速总线集中控制**

```
[CNC / 运动控制器 / PLC+运动模块] ══SSCNET III/H / EtherCAT / CC-Link IE TSN══> [驱动器 1][驱动器 2]…
```

- 一个通讯周期全网刷一遍指令与反馈；插补、同步由控制器统一完成；
- 本目录《CC-Link 通讯详解.md》讲的就是这类（对应 -G/-W 后缀）。

**架构 C：分层网络（工厂级，最常见）**

```
[PC 上位机 / SCADA] ──以太网（MC 协议 / OPC UA）──> [PLC] ══实时总线══> [驱动器]
```

- PC 管数据、配方、监视、参数下发；PLC 管实时控制——**两层都常被叫"上位机"，但分工不同**；
- 调试伺服时通常在 PLC 层做实时验证，PC 层做参数与数据管理。

**架构 D：PC 直控**

```
[PC 软件（C#/LabVIEW）] ──Modbus RTU/TCP 或 EtherCAT 主站──> [驱动器]
```

- 没有 PLC，PC 自己当控制器；测试台、点位设备常用（第十节 Modbus 方式）；
- 实时性上限取决于通道：Modbus 弱（轮询），EtherCAT 主站软件强但要专网卡/主站栈。

> **"上位机"是相对概念**：对伺服驱动器来说，给它发指令的都是上位机（PLC、CNC、运动卡、PC）；而这套 PLC 在 SCADA 眼里又是"下位机"。调试前先问一句：**这台驱动器的指令到底从哪根线来？**——顺藤摸瓜找到的，才是你要对齐的那层"上位机"。

三菱生态对号入座：架构 A = 脉冲型（-A 后缀）；架构 B = SSCNET III/H（-B）、CC-Link IE TSN（-G）、EtherCAT（-W）；架构 C = R 系列 PLC + MC 协议 + PC 软件的常见组合；架构 D = 第十节的 Modbus 方式。调试工具 MR Configurator2 在任何架构里都从"配置通道"插进来，不占指令通道。

## 二、最小术语表（白话版）

### 硬件侧

| 术语 | 白话解释 |
|---|---|
| 伺服驱动器（放大器） | 把指令变成"多大力、怎么转"的功率电子盒子，闭环在这里闭合 |
| 伺服电机 | 配套的永磁同步电机，尾部藏编码器，可带抱闸 |
| 编码器 | 电机的"眼睛"，报位置/速度/磁极（详见本文第四节与《MR-J5 清单》第五节） |
| 绝对 / 增量 | 断电记不记得住位置；记得住 = 绝对式（配 CN6 电池），记不住 = 增量式（上电回原点）——种类详见第四节 |
| 原点 / 回零 | 机械基准点 / 找到它的过程；绝对位置系统可以免回零（建立/回零流程详见第四节） |
| 全闭环 | 位置环改按负载侧的"尺子"（光栅尺/外部编码器）闭合，机械误差一并闭环（详见第四节） |
| 抱闸（制动器） | 断电抱死的刹车，竖轴防坠；松闸必须有时序配合 |
| 再生 | 减速或被拖动时电机变发电机，能量灌回驱动器——再生电阻泄放不过来就报 AL.30 |
| 再生电阻 | 电机被拖动发电（快速减速）时泄放能量的电阻，缺了会报再生异常 |
| STO（安全转矩关断） | 硬线安全功能：切断转矩输出但不断控制电，安全继电器/安全 PLC 常用（比软件急停高一档） |

### 指令侧

| 术语 | 白话解释 |
|---|---|
| 控制模式 | 位置 / 速度 / 转矩三种"听谁的话"的方式，可切换 |
| 指令脉冲 / 脉冲当量 | 脉冲型控制里一个脉冲走多少微米 |
| 指令单位 | 上位机计数的最小单位（比如 1 μm） |
| 电子齿轮 | 指令单位 ↔ 机械位移的换算比例（详见第八节） |
| 加减速 | 指令的斜坡；太陡 = 过流过压报警，太缓 = 跟随差、节拍慢 |
| JOG / 定长 | 点动 / 走固定长度——试运行必备 |

### 状态侧

| 术语 | 白话解释 |
|---|---|
| 伺服 ON（SON） | 使能；不给 SON，驱动器不出力 |
| 伺服准备好（RD） | "可以发指令了"的许可信号 |
| 定位完成（INP） | 滞留脉冲小于设定值 = 判定到位 |
| 滞留脉冲（偏差，droop） | 累计指令 − 累计反馈，即跟随误差 |
| 零速（ZSP） | 实际速度 ≈ 0 的状态信号 |
| 转矩限制中（TLC） | 正在被限力——撞机/过载的前兆 |
| 超调 / 稳定时间 | 冲过头多少 / 多久稳住——调谐好不好就看这两样 |
| 边沿（上升 / 下降） | 信号从无到有 / 从有到无的跳变瞬间——状态机迁移和消抖抓的就是它 |

### 调节侧

| 术语 | 白话解释 |
|---|---|
| 增益 | 三个控制环的"劲道"旋钮 |
| 刚度 / 响应性 | 增益档位的通俗叫法（高刚 = 硬、响；低刚 = 软、稳） |
| 惯量比 | 负载惯量 ÷ 电机惯量，自动调谐的重要输入（选型口径见第五节） |
| 有效转矩（RMS） | 各段转矩按时间平方加权平均的"发热等效转矩"——选型看它不看峰值（公式见第五节） |
| 前馈 | "提前给一把力"的补偿，减小跟随误差 |
| 陷波滤波 | 专门压掉某个机械共振频率点 |

### 反馈与选型侧

| 术语 | 白话解释 |
|---|---|
| Z 相 | 编码器每转一个的基准脉冲——回零"找准"靠它 |
| DOG（原点开关 / 近点狗） | 回零用的行程开关，告诉系统"原点区到了" |
| 磁极 / 换相 | 转子磁铁的当前位置 / 据此决定给 U/V/W 哪相通电（编码器报，接不好一使能就报警） |
| 多圈计数 / 多圈上限 | 绝对式编码器记"断电期间转了几圈"的计数器及其上限——长期单向旋转的设备要设"无限圈" |
| 绝对位置建立 | 告诉编码器"现在这里就是原点"的开机仪式，做完断电重启才生效（第四节实操流程一） |
| 折算 | 把负载惯量/转矩按导程、减速比换算到电机轴上（第五节公式速查） |
| 额定转矩 / 最大转矩 | 连续许用的转矩 / 只许短时冲击的转矩（约 3 倍额定，手册值） |

| 减速机（减速比 i） | 电机与负载之间的减速传动：转矩 ×i，负载惯量折算 ÷i² |

## 三、驱动器内部在干嘛：三环闭环（上位机懂到这里就够）

```
位置指令 →[位置环增益]→ 速度指令 →[速度环增益]→ 转矩指令 →[电流环]→ 电机
              ↑ 位置反馈 ────────────↑ 速度反馈 ────────↑ 电流反馈 ──┘
                                  （编码器 / 电流传感器）
```

- 三个环由内到外一圈比一圈快：**电流环（微秒级）→ 速度环 → 位置环**。外面一圈的输出就是里面一圈的指令。
- 上位机视角的三条结论：
  1. 你发的指令是"目标"，驱动器拿它和编码器报来的事实做差、再补——所以**动作天然滞后**，不是故障；
  2. **滞留脉冲 = 累计指令 − 累计反馈**。运动中它不为零是正常的（正在追）；INP 就是"滞留脉冲小于设定值"的到位判定；
  3. 增益低 → 软、跟得慢；增益高 → 硬、快、但容易振。增益该由调谐决定，别拍脑袋抄。

## 四、编码器：种类、型号与作用（反馈的"事实"从哪来）

三环闭环里的一切"事实"都来自编码器：位置环拿它算误差，速度环拿它算转速，连"该给 U/V/W 哪相通电"（换相）都靠它。编码器装在电机尾部、随电机一体出厂（HG 系列自带，不另购、不可单独维修——坏了就是换电机或返厂），所以对上位机工程师来说，重点不是"选型采购"，而是**认识它、用好它、别冤枉它**：很多"走不准、不到位、莫名漂移"，追到最后都落在编码器或它的线缆上。

（编码器接口、接线与 CN 位置的讲法见《MR-J5 资料下载与文档清单.md》第五节；本节展开作用、种类、型号与上位机落点。）

### 编码器的作用：一口气报四件事

| 它报什么 | 驱动器拿去干嘛 | 对上位机的直接后果 |
|---|---|---|
| ① 位置 | 位置环反馈、滞留脉冲（累计指令 − 累计反馈）计算 | 实际位置、INP 到位判定、软限位、多轴协调全建立在它上面；电子齿轮的分母也出自它 |
| ② 速度 | 速度环反馈 | ZSP 零速判定、抱闸时序、稳速品质的源头 |
| ③ 转子磁极位置 | 换相：决定三相电流往哪通 | 编码器没接好，一使能就报编码器类报警，电机纹丝不动 |
| ④ 自身诊断 | 编码器异常、过速、温度等状态 | 编码器族报警（AL.16/20/21/25）的第一手来源 |

> 一句话：**编码器报的位置不对，"伺服"二字就不成立**——它是闭环里唯一不能糊弄的环节。

进阶用法——**全闭环**：在负载侧再加一把"尺子"（光栅尺或外部角度编码器，接驱动器 CN3），让位置环按**负载的真实位置**闭合，把联轴器间隙、皮带弹性、丝杠变形这些机械环节的误差一并闭环掉。此时 CN2 电机编码器**仍然必须接**——换相与速度环还靠它；位置环用谁，由参数切换。

```
[驱动器]──动力线──> [电机]──联轴器/丝杠/齿隙──> [负载]
    ↑CN2                                     ↑CN3（启用全闭环才接）
    └ 内置编码器：换相 + 速度环 + 默认位置环
      注意：内置编码器量到的是"电机转角"，
      中间机械环节的误差它全看不见——这就是全闭环存在的理由
```

### 编码器的种类：分四个维度，别搅在一起

**维度一：断电记不记得——增量式 vs 绝对式**（对调试影响最大）

| | 增量式 | 绝对式 |
|---|---|---|
| 工作方式 | 转一圈数一圈：A/B 相 90° 正交脉冲计数，Z 相（每转一个）作圈内基准 | 位置以"码"直接读出（专用串行数据）；断电靠电池（CN6）保持，多圈靠圈数计数器 |
| 断电后 | 失忆，上电**必须回零** | 记得住，上电免回零直接干活 |
| 电池 | 不需要 | 需要（个别机型支持"无电池"短时保持，见下） |
| 上位机标配 | **回零功能**：回零方式（原点开关/挡块/Z 相）、方向、两段速度、原点偏移，做成状态机 | 处理"绝对位置丢失"：换过电池、拔过编码器线后，引导重建原点或设定当前位置 |
| 典型翻车 | 干扰窜进计数 → 位置慢慢漂移；没回零就自动运行 → 全是相对坐标 | 电池耗尽硬撑 → 丢位置报警；多圈计数绕回 → 位置突变（见下） |

- 三菱新一代伺服用**"绝对/增量通用"编码器**：同一颗硬件，由参数选择当绝对式用（配电池）还是当增量式用（免电池）。这是**系统级决策**：要免回零、断电保位置 → 绝对；想省电池、能接受开机回零 → 增量，并把回零流程写扎实；
- **多圈上限**：绝对式的圈数记忆位数有限，长期单向连续旋转的设备（旋转输送、回转塔、凸轮分度）要在参数里设"多圈上限/无限圈"方式，否则计数绕回、位置突变——设定方法以《功能篇》为准；
- **无电池绝对**：部分机型用电容储能做短时断电保持（可保持的时长/圈数有限，机型相关，以《功能篇》为准）——够应付周末停机，长假停机或换电机仍要重建原点。

**维度二：怎么"感知"——光电式 / 磁式 / 旋变**

| 类型 | 原理 | 特点 | 常见于 |
|---|---|---|---|
| 光电式 | 光栅盘 + 光电对管 | 分辨率高；怕灰、怕油、怕强振（靠密封防护） | 伺服电机主流、光栅尺 |
| 磁式 | 磁鼓/磁环 + 磁敏元件 | 皮实耐污；分辨率与精度略低 | 小型/经济型伺服、恶劣环境 |
| 旋转变压器（旋变） | 电磁耦合的模拟信号 | 极耐振、耐温、耐脏；输出模拟量需解码（RDC），精度一般 | 车辆、工程机械、重载 |

调试含义：光电式的敌人是**污染与线缆干扰**（偶发 AL.16 的惯犯，第十一节排查卡）；旋变的敌人是解码精度与增益整定。三菱一体式编码器你换不了，但知道类型能帮你预判故障倾向。

**维度三：装在哪、量什么——内置 vs 外部、旋转 vs 直线**

- **内置（电机本机）编码器**：量电机轴转角，接 CN2，是伺服的默认反馈；
- **外部编码器 / 光栅尺**：量**负载**的实际位移，接 CN3（全闭环）；旋转式（量角度）、直线式（光栅尺，量 mm）都有；
- 关键认知：**内置编码器量的是"电机转多少"，不是"负载走多少"**——联轴器打滑、齿隙、丝杠热变形它统统看不见。定位精度要求高 → 上全闭环，或至少知道误差出在哪一段。

**维度四：输出接口什么样**（接第三方编码器/光栅尺做全闭环时才用得到）

- **增量输出**：A/B/Z 差分脉冲（RS-422/TTL/开路集电极），正交 90°，接收方可 ×1/×2/×4 倍频细分；选型盯两个规格：**每转脉冲数**与**最高响应频率**；
- **绝对输出**：串行协议（SSI、BiSS-C、EnDat 及各家专有协议）——**协议对不上，读出来全是乱码**；
- 全闭环改造选第三方编码器/光栅尺（多摩川、海德汉、雷尼绍、库伯勒、宜科等是常见品牌）时，驱动器支持的编码器类型、当量、分频设定以《功能篇》全闭环章节为准。

### 编码器的"型号"：跟着电机走，看三张表

伺服编码器不是独立选件，**型号随电机一体出厂**。要弄清"这台用的是哪颗"，看三个地方：

**① 世代表：放大器代际 → 编码器规格**（速记口径，**以官方"放大器—电机组合表"和《HG 电机资料》为准**）

| 放大器代际 | 配套电机（口径） | 编码器 | 每转脉冲数 |
|---|---|---|---|
| MR-J2S 及更早 | HC / 早期 HF | 17 位 | 131,072 |
| MR-J3 | HF 系列 | 18 位 | 262,144 |
| MR-J4 | HG 系列 | 22 位 | 4,194,304 |
| MR-J5 | HG 系列 | 26 位 | 67,108,864 |

- 位数每加一位分辨率翻倍：22 位 → 26 位就是 16 倍；26 位 = 2^26 = 67,108,864——**这正是第八节电子齿轮公式里"编码器每转脉冲"那个分母的出处**；
- 位数也决定跨代兼容：老电机配新放大器、新电机配老放大器，都可能"上电就报编码器异常"——动手前先查组合表。

**② 电机铭牌与《HG 系列伺服电机资料》规格表**：编码器分辨率、带不带抱闸、轴端/法兰规格都写在电机型号与规格表里——**买电机就是买编码器**：规格表里是 22 位还是 26 位，直接决定能配哪代放大器。

**③ 配套线缆与电池型号**（CN 接口位置见《MR-J5 资料下载与文档清单.md》第四节；型号示例以《硬件篇》为准）：

- **编码器专用电缆**：型号形如 MR-J5ENSCBL□M，后缀区分长度与接头型式（不同法兰的电机插头不同）；屏蔽线、与动力线分开走线（第十一节排查卡的惯犯源头）、**严禁带电插拔**——带电拔插可能直接损坏编码器；
- **绝对位置电池**：接 CN6（如 MR-BAT6V1SET 一类），有寿命（手册值，数年量级）；电量低先出警告、耗尽即丢位置——把"换电池周期"写进保养计划，上位机软件可把电池警告做成提醒工单。

> 常见误会："能不能单独换一颗更高分辨率的编码器？"——不能。电机与编码器一体标定出厂（含磁极基准），换编码器 = 换电机/返厂重标。真要更高精度，走**全闭环加光栅尺**，而不是换编码器。

### 分辨率 ≠ 精度：一个容易被问倒的问题

- **分辨率**：编码器能分辨的最小角度。26 位 = 每转 6,700 万分度，折算到 10 mm 导程丝杠约 0.15 nm——**纸面值**；
- **定位精度**：实际停住点与目标点的偏差——被齿隙、联轴器扭转、丝杠变形、温漂支配，通常比编码器分辨率差 2~4 个数量级；
- **重复定位精度**：反复回同一点的散差——伺服的强项（机械正常时微米级可达）；
- 对客户/对自己的口径："驱动器 + 编码器"只承诺**分辨率与重复精度**；**绝对精度靠机械质量、标定或全闭环**。别拿"26 位"去承诺绝对精度。

### 实操流程一：绝对位置建立——绝对式的"开机仪式"

**什么时候必须做**（四个时机）：

1. **首次安装调试**——编码器第一次通电；
2. **绝对位置丢失报警（AL.25）之后**——电池未接/耗尽、编码器线被拔过、机械在断电中被转动过；
3. **更换电机或编码器后**——出厂基准没了；
4. 曾在"驱动器断电且电池拔下"的状态停留过——位置可能已丢，保险起见重建。

**前提三件事**：

- CN6 **电池先接好再上电**（顺序反了，白干一遍）；
- 参数里编码器用法已选"**绝对**"（增量/绝对选择，参数号以《参数篇》为准）；
- 机械能被移到**真实的机械原点**（低速 JOG 或手摇；竖轴注意抱闸时序）。

**流程**（MR-J 系通用口径，界面与参数号以《功能篇》绝对位置章节 + MR Configurator2 向导为准）：

```
① 接好电池 → 上控制电源、主电源
② 出现 AL.25（绝对位置丢失）——这是预期内的提示，不是故障
③ 把机械移到机械原点（低速 JOG / 手轮；带驱动器回零功能的可先执行一次回零）
④ 执行"绝对位置建立"：MR Configurator2 的建立向导（或按《通信篇》的原点设定指令）
   ——驱动器把"当前坐标"记为原点，编码器多圈计数器同时归基准
⑤ 断电 → 重新上电 → 确认无 AL.25、位置显示正确
⑥ 低速 JOG 往返验证 + 把"何时、由谁、怎么建立"记进调试记录
```

**要点与易错**：

- 建立**必须在真实机械原点上做**——在半路"设原点"等于全机坐标基准错位，之后所有定位全歪，而且错得理直气壮（每台都一样错）；
- 建立**后必须断电重启一次**才真正存进编码器——不重启直接联机，下次上电又报 AL.25；
- **换电池在控制电源 ON 状态下换**——此时编码器由驱动器供电，拔电池不丢数据；怕就怕"驱动器断电 + 电池拔下"两头都断，停留超过编码器保持时间（手册值）位置就没了；
- 上位机软件设计：上电读 AL.25/电池警告 → 弹"引导建立"页 → 走完流程后自动低速验证 → 放行自动运行。**别把 AL.25 当普通报警给操作工复位按钮**——它复位不掉，必须走建立流程（第十一节"须排因"类）；
- 建立、换线之后位置又可能丢——"严禁带电插拔"和电池保养是绝对位置系统的日常功课。

### 实操流程二：回零（原点回归）——增量式的"每天早自习"

先分清分工：**绝对式只在"建立"时做一次流程一**；**增量式每次上电都要回零**。回零的本质：把编码器的计数值和机械坐标对齐。

三种常见姿势：

| 方式 | 怎么走 | 谁来做 | 特点 |
|---|---|---|---|
| 驱动器回零（DOG 式等） | 参数配好方式/速度/方向，上位机发"原点回归开始"指令（专用端子或报文，名称以《硬件篇》《通信篇》为准），驱动器自己找原点并停准 | 驱动器自动 | 精度好（用到 Z 相）、上位机省事；参数项较多 |
| 上位机自控回零 | 上位机发速度指令：高速压向原点开关 → 减速爬行脱离开关 → 定格为原点（讲究的再补找 Z 相） | 上位机全程控制 | 任何机型可用、逻辑灵活；精度受开关重复性限制 |
| 手动设定 | JOG/手摇到原点，当前值直接设为原点（常与流程一合并做） | 人 | 调试期、没装原点开关的场合 |

驱动器回零的参数要素（名称以《参数篇》为准）：**原点回归方式**（DOG 块式/计数式/挡块式等）、**DOG 开关极性与位置**、**回零方向**、**高速段速度**、**爬行（低速）段速度**、**原点偏移量**（开关位置与机械原点不重合时补差）、**原点地址**（回零后当前值写多少）、回零期间的**转矩限制与超时**。

上位机侧的回零状态机：

```
放行条件：原点回归完了信号（ZP 类，名称以《硬件篇》为准）= ON，才允许自动运行
① 确认无报警、SON→RD 就绪
② 确认软限位不挡回零路径（回零区临时放开或方向避开，按《功能篇》）
③ 发"原点回归开始"（脉冲型：专用端子；总线型：专用对象/控制位）
④ 等待 ZP 上升沿——期间禁止任何其他运动指令
⑤ 超时 / 撞限位 / 触发报警 → 判回零失败 → 禁止自动运行并提示
⑥ 完成后 JOG 微动核对原点；首次调试连做 10 次记散差（坑 10 的实测思路）
```

回零的常见坑：

- **回零速度太快冲过头**：高速段只负责"去找"，开关响应 + 采样延迟都要算进去；**低速爬行段才是"找准"的段**；
- **DOG 开关抖动**：一次回零抓到多个触发沿，重复性差——硬件滤波 + 软件消抖（第七节的消抖原则在这里同样适用）；
- **原点偏移忘了设**：每次回零都差同一个固定量，还冤枉开关装歪了；
- **重复回零散差大** = 开关重复精度差或回零方式没用到 Z 相——实测散差说话，超差就换方式/换开关；
- **把 ZP 当电平逻辑用**：ZP 是状态位，回零完成后一直 ON；要抓的是"从没有到有"的边沿，并配合当前值一起判断；
- **绝对式别画蛇添足每天回零**——除非工艺要求重新对基准，日常上电直接用，这正是当初买电池换来的。

### 落到代码：编码器知识在上位机里的六个落点

1. **电子齿轮的分母来自编码器位数**——2^26 是 26 位机；跨代设备（17/18/22/26 位）分母不同，从配置读，别手写死（第十四节规则 3 的延伸）；
2. **增量式机型：回零是上位机标配功能**——方式、方向、两段速度、原点偏移全部参数化、状态机化（第十四节规则 1），回零未完成禁止自动运行（完整流程见上文实操流程二）；
3. **绝对式机型：上电先查"丢失"**——读 AL.25 与电池警告，弹出"重新建立绝对位置"引导（回原点或示教当前位置），做完才放行自动运行（完整流程见上文实操流程一）；
4. **多轴协调用的是驱动器转发的实际位置**——它是编码器值换算后的汇报，滞后 1~2 个通讯周期（第十四节规则 2），别拿它做毫秒级同步判断；
5. **脉冲型机型：用分频输出核对丢步**——驱动器可把编码器脉冲分频输出（端子名见《硬件篇》），PLC 高速计数器同时数"发的"和"收的"，一比就知道丢步在指令侧还是机械侧；
6. **报警字典带上编码器族**——AL.16（初始通信异常）/ AL.20/21（通信异常/超时）/ AL.25（绝对位置丢失）按第十一节的报警处理状态机分类：16/20/21 多为线缆与干扰（先断电重插、再换线），25 走"电池/重建原点"流程，别当硬件故障报修。

> 报警码为 MR-J 系通用口径，具体定义与处置以《故障排除篇（报警一览）》为准。

## 五、伺服电机选型：把负载的账算到电机轴上

选型是设计阶段的活，但调试工程师必须懂——因为**现场一大半"调不好"，根子在选型欠账**：转矩余量不足、惯量比过大、再生没算、代际不配套。这些欠账平时藏着，一上电就从报警窗口冒头。这一节给出上位机视角的最小选型账本：看懂图纸、评方案、跟机械工程师对话、查备件，都够用（精确计算走厂家选型软件，本节是"看得懂、查得出、对得上"的口径）。

### 选型四步账：先算账，再对表

| 步骤 | 算什么 | 要点 |
|---|---|---|
| ① 折算负载 | 把工作台、工件、丝杠、滚筒、皮带的**惯量与转矩**折算到电机轴 | 见下方公式速查；细长丝杠、重工件最容易被漏算 |
| ② 算转速 | 负载线速度 ÷ 导程（÷减速比）→ 电机常用转速 | 对电机的**额定转速**（连续）与**最高转速**（只许短时）分清 |
| ③ 选转矩 | 摩擦/重力等**负载转矩** + 加速转矩 → 核对**有效转矩（RMS）与峰值转矩** | 有效转矩看发热（负载率口径见下），峰值转矩看加速瞬间 |
| ④ 核惯量比 | 折算负载惯量 ÷ 电机转子惯量 | 直接决定调谐难度（第八节）；过大先上减速机，别死调增益 |

### 折算公式速查（工程近似）

```
转速        n = 60 × v / P                       v：线速度 [m/s]，P：导程 [m]

折算到电机轴的惯量：
直线负载（台+工件，走丝杠）  J = m × (P / 2π)²        m：质量 [kg]
滚筒/丝杠本体（实心圆柱）    J = m × D² / 8           D：直径 [m]（丝杠用 D⁴ 版本：πρLD⁴/32）
皮带及带上负载              J = m × D² / 4           质量按"挂在滚筒外圆上"折算
经减速机 i:1 折入           J' = J / i²              减速机是"惯量比的朋友"：转矩 ×i，惯量比 ÷i²

转矩：
水平轴摩擦      T = μ·m·g·P / (2π·η)             η：丝杠效率（滚珠丝杠 ≈0.9）
垂直轴重力      T = m·g·P / (2π·η)               竖轴必算，抱闸容量也按它核
加速转矩        T = J_total × 2π·n / (60·t)      n [r/min]，t：加速时间 [s]，J_total 含转子
有效转矩        T_rms = √( Σ(T_i² × t_i) / Σt_i )   把节拍各段转矩×时间代入；
                                                    停止段转矩≈0，但时间要计入分母
```

**别漏项清单**：工件（最重且会换！）、丝杠本体惯量、联轴器、减速机自身惯量、皮带+随动件、导轨摩擦、垂直轴重力、外部反力（压装/切削力）、减速机与丝杠的效率、加减速时间——公式都是几行，漏项才是主犯。

### 一道示意小账（看数字怎么流）

条件（教学示意，实机按手册数据重算）：工作台+工件 50 kg，导程 10 mm，快移 300 mm/s，加速 0.1 s，丝杠+联轴器折算 0.5×10⁻⁴ kg·m²，摩擦系数 0.1，η=0.9：

- 常用转速 n = 60 × 0.3 / 0.01 = **1800 r/min** → 对额定 3000 r/min 级电机余量充足；
- 直线负载惯量 J = 50 × (0.01/2π)² ≈ 1.27×10⁻⁴，加丝杠等 ≈ **1.77×10⁻⁴ kg·m²**；
- 设电机转子惯量 0.87×10⁻⁴ → **惯量比 ≈ 2 倍**，调谐好调；
- 摩擦转矩 ≈ 0.1×50×9.8×0.01/(2π×0.9) ≈ **0.09 N·m**；加速转矩 ≈ 1.77×10⁻⁴ × (2π×1800/60)/0.1 ≈ **0.33 N·m**（峰值需求 ≈ 0.42 N·m）；
- 拿"有效转矩/峰值转矩/惯量比/常用转速"四个数去对电机规格表（数据以《HG 电机资料》为准），选型四步账即闭环——选了电机，驱动器容量按组合表跟着走。

### 余量与经验口径（数值以厂家推荐为准）

- **有效转矩负载率 ≤ 80%**：留热余量；频繁启停、高温环境、高占空比再压到 60~70%；
- **峰值转矩**：最大加速转矩 × 安全余量 ≤ 电机最大转矩（通常为额定的 3 倍左右，手册值）；
- **惯量比经验带**：通用机械 10 倍内轻松调，20~30 倍要下功夫（陷波、前馈齐上，第八节），再大就减速机压惯量比；
- **转速**：常用工况 ≤ 额定转速；别让电机常年跑在最高转速段——转矩会掉、发热会涨；
- **再生**：频繁加减速、竖轴、大惯量急停的场合按手册公式核算再生功率，内置电阻不够就加外置再生电阻（否则等你的就是 AL.30，第十节）。

### 配套核对清单（选型 ≠ 只算转矩）

- **电压等级与驱动器后缀**：220 V 级 / 400 V 级要与现场电网一致（驱动器型号后缀区分）；
- **编码器代际必须与放大器配套**：22 位还是 26 位决定配 J4 还是 J5（第四节世代表）——换备件时最容易被忽略的一条；
- **增选件**：抱闸（竖轴防坠，配合时序见第六节与坑 9）、油封（切削液环境）、防护等级、轴端/法兰尺寸；
- **传动件**：减速机（压惯量比、提转矩）、联轴器刚度（影响共振，第八节）；
- **电源侧**：主电路容量、断路器/电抗器选型（按《硬件篇》，本篇不展开）。

### 选型欠账在调试现场长什么样

| 现场症状 | 选型上的第一嫌疑 |
|---|---|
| TLC 常亮、高速段转矩顶格（坑 4） | 转速/转矩余量不足，减速比没选好 |
| 加减速段 AL.32/33、AL.30 | 惯量大、斜坡陡、再生能力不足 |
| 温升高、跑久了 AL.50/51 | 有效转矩负载率超 80%、占空比太高 |
| 增益一高就振、一低就软（第八节） | 惯量比过大——减速机是解药 |
| 竖轴断电下滑（坑 9） | 重力转矩没进账、抱闸容量/时序问题 |
| 定位慢半拍、AL.52 频发 | 转矩余量不足或惯量比大，指令还太快 |

顺手把"选型账"（惯量折算、负载率、再生核算）存进设备档案，报警时对照能省一半猜——与参数快照制度（第十四节规则 7）是兄弟条款。

> 口诀：**转矩看有效，转速看常用，惯量比压小，代际要对上；余量留两成，再生别硬扛。**

## 六、控制模式与指令形态

| 模式 | 上位机发什么 | 典型用途 |
|---|---|---|
| 位置模式 | 脉冲数 / 目标位置报文 | 定位、进给轴 |
| 速度模式 | ±模拟电压 / 速度报文 | 主轴、输送线 |
| 转矩模式 | ±模拟电压 / 转矩报文 | 张力控制、压装 |
| 模式切换 | 专用信号或报文切换 | 一个轴多种工艺 |

指令形态三大家族：

- **脉冲型**：脉冲 + 方向 / 正反双脉冲 / 正交 90°（A/B 相）。上位机要有高速脉冲输出口，加减速也由上位机做；驱动器参数里的"指令脉冲形态"必须和上位机发的一致。
- **模拟量型**：±10V 对应额定速度/转矩。受 DA 精度和零漂影响，精度要求高时要注意调零。
- **总线型**：报文里直接写目标值（EtherCAT 的 CSP/CSV/CST，或三菱的 RWw 映射）。指令周期 = 通讯周期，同步最好；脉冲当量的换算交给电子齿轮/报文单位约定。

上位机要点：**指令源要切对**。总线机型残留着脉冲模式的参数设定，报文写得再对也没反应——这是"写了没动静"的高发原因（同《CC-Link 通讯详解.md》坑 4）。

## 七、上位机必须拿捏的 I/O 信号与时序

核心信号（硬线接在 CN1；总线机型映射成 RY/RX 位，含义不变）：

输入（上位机 → 驱动器）：

| 信号 | 含义 | 上位机要做什么 |
|---|---|---|
| SON | 伺服 ON | 置位使能，之后等 RD |
| RES | 复位 | 清报警，做成**脉冲** |
| LSP / LSN | 正/反转行程末端 | 外部限位，必须接好（或确认参数允许不用） |
| EM2 / EMG | 外部急停 | 走硬件安全链路，不经过软件 |

输出（驱动器 → 上位机）：

| 信号 | 含义 | 上位机怎么用 |
|---|---|---|
| RD | 伺服准备好 | 发指令的许可 |
| INP | 定位完成 | 到位判定 |
| ALM | 故障 | 出错停机，读报警码 |
| TLC | 转矩限制中 | 撞机/过载前兆，尽早预警 |
| ZSP | 零速 | 停转判定 |
| MBR | 抱闸控制 | 带抱闸电机按正确时序松/抱闸 |

一轮完整动作的时序（一分钟版）：

```
SON ──↑ ……(驱动器自检/主电路充电)…… RD ──↑ → 此时才允许发指令
指令 ──→ 运动 ──→ INP ──↑（滞留脉冲进入允差，到位）
报警时：ALM ──↑，驱动器按设定的停止方式停车；排除故障 → RES 脉冲 → 重新 SON
```

### 信号的物理面：硬线端子 vs 总线位

- **硬线侧（-A 机型，CN1）**：DC24V、光耦隔离，输入分**漏型（sink）/源型（source）**接法——上位机侧 I/O 的型式必须与驱动器配对，接错就是"信号怎么给都没反应"的第一大疑惑；
- **端子功能是参数分配的**，不是焊死的：哪个端子当 SON、哪个当 RES 由 I/O 分配参数决定——改了分配，上位机程序要同步改；
- **总线侧（-B/-G/-W）**：同样的信号映射成总线位（RX/RY 或 PDO），含义不变，但多了两个时序效应——**滞后一拍**（本节最后一小节）与轮询/扫描延迟；
- 调试第一步永远是：打开 MR Configurator2 的 **I/O 监视页**，确认"我给的这个信号驱动器真的收到了"，再谈时序。

### 逐个信号讲时序：置位后发生什么，撤销后发生什么

信号是个"生命周期"：置位/亮起只是一瞬间，**撤销/断开时的行为**才是最容易踩坑的地方。

**SON（伺服 ON）**

- 置位后：主电路充电 → 自检（编码器通信、参数校验）→ 就绪后输出 RD；充电+自检典型几百 ms~1 s 量级（视容量，以手册为准），**这段窗口内发的指令会被丢弃**；
- 撤销后：立即撤转矩、按设定方式停车——**位置保持同时消失**，竖轴必须配抱闸时序（坑 9）；
- 易错：把 SON 当"启动按钮"反复开关；在充电窗口里发指令（表现为"偶尔丢步/没反应"）。

**RD（伺服准备好）**

- 亮 = 控制电源、主电路、编码器通信全部就绪，**允许发指令**——它是"开始"的许可，不是"完成"的信号；
- 一直不亮的排查链：有无报警 → EM2/急停链路 → 主电路电压（坑 2 的排查步骤）。

**INP（定位完成）**

- 亮 = 滞留脉冲（累计指令−累计反馈）落进"定位完成范围"参数；**运动中不亮**（正在追），停稳后才亮；
- 易错：它只在位置环语义下成立，速度/转矩模式下的输出含义不同（以《功能篇》为准）；到位判定要 INP + 滞留监视**双确认**（坑 10）。

**ZSP（零速）**

- 实际速度低于阈值 → 亮；抱闸轴"可以抱闸了"的判据、停止确认用；
- 易错：默认阈值未必匹配抱闸时序，竖轴要按防坠落要求核算阈值与延迟。

**TLC（转矩限制中）**

- 输出转矩被限制 → 亮；加减速段偶尔亮属正常，**一直亮 = 堵转/过载/参数没放开**（坑 4）——当预警位用，别忽略。

**ALM（故障）**

- **常闭（B 接点）语义**：正常导通、报警时断开——线断、插头松，上位机看到的就是"报警"，刻意的 fail-safe 设计；**程序必须按常闭逻辑写**：读不到"导通"一律按报警处理，而不是当无报警；
- 报警发生：按参数设定的停止方式停车并锁存报警码；复位规矩（可直复位/须断电/须排因）见第十一节。

**RES（复位）**

- 置位期间清报警、复位内部状态；宽度要够（手册值，通常几十 ms 以上），复位后回读报警码确认清零；
- 易错：长电平复位（坑 3）、复位前不取证（第十一节六步流程）。

**LSP / LSN（正/反转行程末端）**

- 断开后：该方向的新指令被禁止；运行中触发则按参数设定的方式停（急停停/减速停）；
- 易错：想当然"断开 = 立即停"——默认行为以《参数篇》为准；软限位与硬限位之间要留**真实余量**，别让软限位形同虚设。

**EM2 / EMG（外部急停）**

- 断开：立即按急停方式停车（不走你的减速曲线），通常伴随使能撤销；
- 归属硬件安全链路：软件只读不拦（规则 6）。

**MBR（抱闸控制）**

- 驱动器按参数时序联动抱闸（与 SON/ZSP 的配合、松闸/抱闸延迟）；完整时序与实测法见坑 9，一句话：**有保持力才松闸，先抱闸再撤 SON**。

### 停止方式：同样"停下来"，姿势完全不同

| 停止方式 | 动作 | 停止距离 | 冲击 | 典型用途 |
|---|---|---|---|---|
| 动态制动（DB） | 电机绕组短路泄能 | 短、快 | 大 | 急停、报警、竖轴兜底 |
| 减速停止（缓停） | 按减速参数走斜坡 | 长 | 小 | 限位触发、正常停机 |
| 自由停车（coast） | 撤转矩让轴滑停 | 不受控 | 无 | 允许滑行的场合 |

关键认知：**"停下来"的方式是逐事件配置的参数，不是全机统一**——同一台驱动器，撤 SON、EM2 断、限位断、报警发生，各自可配不同的停止方式。

- 竖轴/大惯量场合：停止方式选错 = 坠落或撞机，逐项按《功能篇》核对；
- 急停停止（DB）类快速停车把机械动能灌回驱动器——再生电阻核算（AL.30）与这里联动（第十一节）；
- 上位机要按"每种事件各自的停止方式"设计等待逻辑：EM2 断后的停止 ≠ 限位触发后的停止，别共用一个"停止完成"假设。

### 分阶段拆开看：一轮动作的完整时序

| 阶段 | 上位机动作 | 驱动器内部在干嘛 | 等待信号 | 典型耗时 |
|---|---|---|---|---|
| 上电 | 上控制电源 → 主电源 | 初始化、编码器通信建立 | 面板正常、无报警 | <1 s |
| 使能 | 置 SON | 主电路充电、自检 | RD | 几百 ms~1 s |
| 发令 | 写目标/给脉冲 | 三环闭环追指令 | —— | 指令周期级 |
| 到位判定 | 停发目标 | 滞留脉冲收敛进允差 | INP | 数十 ms |
| 零速确认 | —— | 实际速度低于阈值 | ZSP | —— |
| 去使能 | 先抱闸（竖轴）→ 撤 SON | 按设定方式撤转矩停车 | —— | —— |

```
上电      ────↑
SON       ──────────↑─────────────────────────────
RD        ────────────────────↑────────────────────   ← 此后才许发指令
指令      ──────────────────────────↑──────────┐
INP       ────────────────────────────────────────↑─────   ← 滞留进入允差（位置模式）
ZSP       ──────────────────────────────────────────↑───   ← 速度≈0，竖轴在此后抱闸
SON       ─────────────────────────────────────────────↓   ← 停机：先抱闸再撤 SON
```

- 图上两处最容易错：**RD 之前发指令**（坑 2）和 **ZSP 之前抱闸/撤 SON**（坑 9）；
- "使能"阶段的耗时是弹性的（充电电压、环境温度都影响）——所以规则 1 要求**等信号不等时间**。

### 总线机型的 I/O 时序：滞后一拍与消抖

- 写 RY → 下一通讯周期从站才执行 → 从站状态变化 → **再一拍后 RX 才反映回来**：从"我给了"到"我看到了"最少隔 2 个通讯周期（机制见《CC-Link 通讯详解.md》第五节）；
- 程序含义：任何"写位 → 立刻读位"的判断都太早（规则 2）；等信号的超时下限 = 2 个通讯周期 + 消抖时间 + 余量；
- 硬线侧同样有输入滤波（数字滤波参数，ms 级防抖）；软件再加一层消抖，毛刺就进不了状态机。

### 上位机软件读 I/O 的细节

- **消抖**：普通状态信号连续 2~3 个采样周期一致才认（5 ms 周期 × 3 ≈ 15 ms 确认）；
- **安全信号少消抖**：ALM、EM2 的硬件滤波已经够用，软件再叠多拍消抖等于拖慢安全反应——只有运动状态类信号才做多拍消抖；
- **边沿日志**：SON/RD/ALM/EM2/限位全部记录"时刻 + 上升/下降"，排查"谁先谁后"全靠它；
- **双确认**：到位 = INP 位 + |滞留脉冲| < 阈值 同时满足（坑 10）；
- **位是结论，监视值是过程**：排查时信号位 + 监视值（滞留、转矩 %）一起看。

```csharp
// I/O 消抖监视器（示意）：连续 N 次一致才更新，边沿即日志
class DebouncedInput(Func<bool> read, int need) {
    bool _last, _stable; int _hits;
    public bool Stable => _stable;
    public event Action<bool>? Changed;

    public void Sample() {                          // 固定周期调用（如每 5 ms）
        bool v = read();
        _hits = (v == _last) ? _hits + 1 : 1;
        _last = v;
        if (_hits >= need && v != _stable) {
            _stable = v;
            Changed?.Invoke(v);                     // 边沿事件
        }
    }
}

var rd = new DebouncedInput(() => io.RD, need: 3);   // 约 15 ms 确认
rd.Changed += up => Log.Io($"RD {(up ? "↑" : "↓")}"); // 谁先谁后，日志说话
```

铁律四条：

1. SON 之后**必须等 RD** 再发指令；
2. 报警复位做成**脉冲**，一直按着可能掩盖真实故障；
3. 急停和限位走**硬件**，别只做在软件里；
4. 竖轴带抱闸：先 SON 再松闸（MBR），停止时先抱闸再伺服 OFF，防坠落——时序配合驱动器有专用参数（以《硬件篇》《功能篇》为准）。

## 八、参数：上位机要会读会改的那几十个

参数大致分几类：**基本设定**（控制模式、指令单位/电子齿轮、加减速）、**增益/调谐**、**I/O 定义**、**扩展专题**（绝对位置、全闭环、抱闸、通信）。

上位机最该吃透的几个：

- **电子齿轮（最重要）**：把"上位机的 1 个指令单位"换算成"机械走多少"。
  公式：**电机每转所需指令脉冲 = 编码器每转脉冲 ×（齿轮分子 ÷ 齿轮分母）**。
  例：丝杠导程 10 mm，想让 1 指令单位 = 1 μm，则每转需要 10000 单位，分子/分母 = 10000 ÷ 67108864（再按参数允许范围化简；67108864 = 2^26，即 26 位编码器每转脉冲——出处见第四节）。分子分母颠倒 → "走 10 mm 实走 0.01 mm"或直接疯跑，**第一大坑**。具体分子分母的取值范围以《参数篇》为准。
- **INP 范围**：多大算"到位"。设太大 → 假到位；太小 → 永远报没到位。
- **转矩限制**：试运行阶段先压低（如 50%），护住机械和人。
- **报警时的停止方式**：动态制动/自由停车等，直接影响停止距离——竖轴和大惯量场合必须核对。
- **参数生效时机**：多数写完立即生效，个别要断电重启才生效——**写完回读确认**，必要时按《参数篇》的"生效条件"列执行。
- **备份/恢复**：上位机软件的标配能力：调试前读出全部参数存档，改坏随时回滚（MR Configurator2 支持，自研软件也应做）。

## 九、增益与调谐（上位机视角的最小集）

- 名词对上号：**位置增益 / 速度增益 / 速度积分补偿** 分别对应三环的旋钮；参数里的"刚度/响应性"档位是一组配好的预设。
- **惯量比** = 负载惯量 ÷ 电机惯量。自动调谐靠估它来配增益，**估错则调谐结果飘**——所以机械参数尽量填实（折算公式与经验口径见第五节）。
- **自动调谐**：让轴做几次小往返，驱动器估惯量、配增益——90% 的现场够用。
- **一键调谐 / 实时自动调谐**（MR Configurator2 内）：边跑边调，适合追响应。
- 什么时候需要手动：机械共振（加**陷波**）、齿轮间隙（低速爬行/异响）、追求极小跟随误差（加**前馈**）。
- 上位机工具配合：用**示波器**抓"指令 vs 实际速度/位置、转矩"，看超调量、稳定时间、转矩毛刺——比看参数表有用得多。

### 共振、谐波、陷波——调谐时的"杂音"到底是什么

先分清两个常被混着说的词：

- **谐振 / 共振（resonance）**：一种"现象"。机械都有**固有频率**——想象弹簧挂着质量块，拨一下就按固定频率晃。当增益调高或转速产生的激励接近这个频率，振动被放大：轻则波形发毛，重则啸叫、撞机。
- **谐波（harmonics）**：一种"波形成分"。任何周期性波形都能拆成"**基频** + 基频的 2 倍、3 倍…（各次**谐波**）+ 噪声"。比如转矩纹波不是正弦，用 FFT（频谱分析）拆开看，就是 1 次、2 次、3 次……成排的频率成分。

一句话：**谐波是频谱里的"成分"，共振是某个成分被机械"放大"。** 调谐要处理的大多数麻烦，是"共振把某段频率放大了"。

> 别混：这里的"谐波"与"谐波减速器"（一种靠柔轮变形传动的减速机构，机器人上常见）只是重名——一个是频谱成分，一个是机械部件。

为什么会碰到这些：

- 驱动器的电流环和 PWM 开关本身会给转矩/电流带来高频纹波——这是谐波源之一，但幅值小、频率高，通常无感；
- 机械（联轴器、丝杠、皮带、悬臂）的固有频率从几十到几千 Hz，恰好落在增益调高后驱动器激励得到的区间——这就是"**增益一高就啸叫**"的原因；
- 齿槽效应（cogging）、转矩纹波带来的谐波成分，频率与转速成比例：转速越高，频谱上的峰越往右移。现场定位口诀：**跟着转速跑的峰 = 机械/电机源；固定不动的峰 = 电气/整定源**。

上位机怎么对付（五步排查链）：

1. 听到啸叫 / 看到波形发毛 → 先**降增益**确认：降了就安静，基本是共振作怪；
2. 用 MR Configurator2 的**示波器 + FFT / 机器分析**抓转矩或速度频谱，记下尖峰的频率；
3. 把尖峰频率填进驱动器的**陷波滤波器（notch）**。陷波三要素：**中心频率**（坑挖在哪）、**衰减深度**（挖多深）、**宽度 / Q 值**（挖多窄，Q 越大坑越窄）。坑要窄而深、对准尖峰——挖太宽会连带削掉有效响应，相位滞后、手感变"肉"；
4. 共振点不止一个时（长悬臂、龙门常见），用驱动器的**共振抑制滤波器组**逐个压，部分型号支持自动检测共振点；
5. 压完共振，再把增益往回调高，重抓示波器确认没有新尖峰。

顺带分清两种"抖"，别都当成谐波问题：

| 现象 | 频段 | 多半是 | 先动什么 |
|---|---|---|---|
| 低频晃动、来回摆 | 1~几十 Hz | 位置环增益与惯量比不匹配、机械间隙 | 降位置增益、查齿轮间隙 |
| 高频振动、啸叫 | 几十 Hz~几 kHz | 共振被放大、陷波没对准 | FFT 找峰 → 陷波 → 再升增益 |

## 十、通信：上位机怎么"够得着"驱动器

两类口别混：

| 用途 | 物理口 | 上位机形态 |
|---|---|---|
| 调试 / 配置 / 监视 | USB（CN4）、RS-485（CN8）、以太网 | MR Configurator2、自研 PC 软件 |
| 实时控制 | 脉冲 / 模拟量、SSCNET III/H、CC-Link IE TSN、EtherCAT | PLC / CNC / 运动控制器 |

- 调试口走的是"**寄存器读写**"式报文：读参数、写参数、读状态、读报警历史。RS-485 一条总线挂多台靠**站号**区分，上位机轮询。
- **EtherCAT（-W）走 CiA402 状态机**，上位机必须按状态机顺序走：
  - 使能序列（控制字 6040h）：故障复位 0x80 → Shutdown 0x06 → Switch on 0x07 → Enable operation 0x0F；状态字（6041h）的位逐步就绪，跳步驱动器就不使能——又一个"写了没反应"的高发原因；
  - 模式字（6060h）：1=轮廓位置、3=轮廓速度、8=同步位置（CSP）、9=同步速度（CSV）、10=同步转矩（CST）；
  - 常用对象：目标 607A（位置）/60FF（速度）/6071（转矩），实际 6064/606C/6077。
  - 以《通信篇》EtherCAT 分册与 CiA402/ETG 规范为准。
- **CC-Link IE TSN（-G）**：RX/RY/RWw/RWr 循环映射 + 瞬时报文，机制与坑详见《CC-Link 通讯详解.md》第四、五节。
- 通用设计点：**心跳/看门狗与超时**时间要设；报文里写的是**指令单位**（参数约定），不是物理单位，换算别做两次；多台轮询要预算周期。

### 用 Modbus 控制普通伺服：最通用的第三方路数

先划清边界：三菱 MR-J5 的控制不走通用 Modbus（-G 走 CC-Link IE TSN、-W 走 EtherCAT、CN8 是三菱专用协议）；但市面上大量"普通伺服"（汇川、台达、信捷等）把 Modbus 当标配控制口——**没有脉冲口、没有现场总线时，Modbus 就是上位机控伺服的默认姿势**，C#（NModbus）、Python（pymodbus）都有成熟库，CRC、超时、重试不用手搓。

**1. 协议本身的三个常识**

- **主从问答**：只有上位机（主站）发起，驱动器（从站）被动应答；站号 1~247，RS-485 一条线挂多台靠站号区分。
- **两种封装**：RTU（跑在 RS-485 上，帧尾带 CRC16）与 TCP（跑在以太网，端口 502，无 CRC）。寄存器模型完全一样，换封装不换逻辑。
- **四类数据 + 功能码**：线圈（0x01/0x05/0x0F，开关量）、离散输入（0x02）、输入寄存器（0x04，只读）、**保持寄存器（0x03 读 / 0x06 单写 / 0x10 连写）——控制伺服几乎全靠保持寄存器**。

**2. 驱动器侧的约定：一张寄存器表 + 一台"寄存器状态机"**

伺服从站把控制字、状态字、模式、目标值、实际值、参数都映射成保持寄存器（地址见各家手册的 Modbus/通信章节）。控制流程普遍长成一个模样，和 CiA402 一个思路：

```
写"控制字"寄存器（使能 / 故障复位）
  → 读"状态字"寄存器，等对应位就绪
写"模式"寄存器（位置 / 速度 / 转矩）
写"目标值"寄存器（32 位 → 连续两个 16 位寄存器）
  → 置"新指令 / 触发"位（注意手册里是边沿还是电平）
轮询：状态字（到位位 / 故障位）+ 实际值（位置 / 速度 / 转矩）
故障时：读"故障码"寄存器 → 排除 → 控制字写复位
```

台达、汇川等主流品牌都是这个骨架（控制字—状态字—模式—目标值），吃透一台，换品牌基本只是换地址表。**寄存器地址和状态机定义以各家手册为准，别拿 A 品牌的地址去写 B 品牌。**

**3. 上位机软件要处理好的五件事**

1. **32 位值的字序**：位置、速度这类 32 位值拆成两个 16 位寄存器，**高低字先后各家不同**，错一位数值就面目全非——第一次通讯务必写完回读验证。
2. **有符号数**：反向的速度/位置是负数，寄存器里是补码，读出来要转换。
3. **单位与缩放**：寄存器里通常是"指令单位/编码器单位"，不是 mm——和第八节电子齿轮是同一件事，换算集中一处做。
4. **轮询节奏**：RTU 一次事务毫秒到几十毫秒（视波特率与寄存器数）。把状态字、实际位置、实际转矩**排成连续地址一次 0x03 读回**，别一个寄存器发一个事务；写目标值也尽量用 0x10 连写。
5. **平滑不靠流式刷目标**：Modbus 没有同步周期，别想着每几毫秒刷一点目标值走出丝滑轨迹——正确姿势是**下阶梯目标 + 让驱动器内部的加减速斜坡去磨平**。

顺带几个高频坑：RS-485 的 **A/B 线接反**（整条线无应答）、**站号/波特率/校验位**不一致（奇偶、停止位要逐台核对）、写只读区收到异常码（0x01/0x02/0x03 = 非法功能/非法地址/非法数据，按码排错）、从站偶发无应答要留**重试一次 + 超时**。

**4. 边界：什么时候别用 Modbus 控伺服**

| 需求 | Modbus 够不够 |
|---|---|
| 单轴定位、点位、速度段、参数读写 | 够，最常用 |
| 轴状态监视、简单联动（靠上位机逻辑拼） | 够 |
| 多轴插补、电子凸轮、严格同步 | 不够——无同步周期，轮询抖动直接进运动 |
| 高响应伺服（高刚度、毫秒内到位） | 不够——轮询周期就是指令延迟的下限 |

一句话：**Modbus 控伺服 = "寄存器状态机 + 阶梯目标 + 驱动器斜坡"**，点位场景便宜好用；要丝滑和同步，还是上总线（EtherCAT / CC-Link IE TSN）。

## 十一、报警与诊断（上位机怎么查）

报警从哪来：驱动器面板、通信寄存器/状态字、ALM 位 + 报警码。

MR-J 系通用报警族（速查口径，**以《报警一览》为准**；E 开头多为警告，不停机）：

| 报警 | 含义 | 上位机侧先查什么 |
|---|---|---|
| AL.10 | 主电路欠压 | 供电电压、缺相 |
| AL.16 | 编码器异常 | 编码器线、插头、干扰（是否与动力线捆走） |
| AL.20 / 21 | 编码器通信异常 / 超时 | 线缆、插头、干扰——先断电重插再换线（第四节） |
| AL.25 | 绝对位置丢失 | 电池未接/耗尽、编码器线拔过——按第四节实操流程一重建原点 |
| AL.24 | 主电路/输出短路类 | 接线、电机线对地 |
| AL.30 | 再生异常 | 再生电阻选件、减速是否过猛 |
| AL.32 / 33 | 过流 / 过压 | 机械卡死、加减速是否太狠 |
| AL.37 | 参数异常 | 参数被写坏、参数与固件版本不符 |
| AL.45 / 46 | 过热（放大器 / 电机） | 负载率、散热、频繁启停 |
| AL.50 / 51 | 过载 1 / 2 | 负载惯量、转矩限制、机械别劲 |
| AL.52 | 误差过大（滞留超限） | 增益过低、指令太快、机械堵转 |

### 报警排查的通用流程（六步，先取证后动手）

```
报警发生
  ↓
① 冻结现场：记录报警码 + 报警历史 + 发生时刻的运行状态（速度/转矩/位置）
  ↓            （别急着复位——现场没了就查不下去）
② 按"发生时机"分类（见下表）
  ↓
③ 对应"分类排查卡"逐项排因，一次只改一处
  ↓
④ 排除后复位：脉冲复位；该断电的断电
  ↓
⑤ 低速 JOG 验证 → 恢复正式参数 → 联机
  ↓
⑥ 复现测试跑够时长（间歇性故障最会装死：线缆、干扰、热累积）
```

**按发生时机分类**——发生时机本身就是最大的线索：

| 发生时机 | 典型报警 | 第一怀疑对象 |
|---|---|---|
| 上电即报（还没动过） | AL.16、AL.25、AL.37、AL.10 | 编码器线、电池、参数、电源——与运动无关，**别去调增益** |
| 使能（SON）瞬间报 | AL.24、AL.32、AL.30 | 主电路接线、对地短路、抱闸没开 |
| 给指令/加减速时报 | AL.52、AL.32/33、AL.50 | 指令太快、斜坡太陡、增益太低、机械堵 |
| 匀速/特定速度段报 | AL.30、AL.46 | 再生、共振（见第九节）、过热累积 |
| 偶发/不定时报 | 各种 | 接线松动、干扰、热累积——翻报警历史找时间规律 |

### 分类排查卡

**电源类（AL.10 欠压）**

1. 监视/实测主电路端子电压，与铭牌额定比；
2. 万用表逐项查：缺相？线路压降？同电源大负载启动瞬间拉低？
3. 核对上电时序（控制电源先于主电源）与急停触点是否造成瞬时断电。

**编码器类（AL.16 / 20 / 21 / 25）**

1. 断电重插 CN2 两端接头——氧化、虚插最常见，先做这个（编码器线**严禁带电插拔**：先断控制电与主电再动手，带电拔插可能损坏编码器本身）；
2. 换一根编码器线（备件法一步二分"线 or 电机"）；
3. 查走线：编码器线与动力线捆在一起、屏蔽层没接地 → 干扰型偶发报警的惯犯；
4. 换线仍报才怀疑电机编码器本体，走更换流程；
5. **AL.25（绝对位置丢失）单独走一条线**：查 CN6 电池（没接/耗尽/编码器线拔过）→ 重新建立绝对位置（回原点或示教当前位置），别当硬件故障报修（详见第四节）。

**过载类（AL.50/51）**

1. 监视负载率/输出转矩 % 曲线：是持续偏高还是瞬时尖峰触发；
2. **脱开负载空跑对比**：空跑还报 → 参数/选型问题；空跑不报 → 机械别劲/负载惯量问题；
3. 查节拍：频繁启停 + 高负载率 = 热累积过载；
4. 复核选型余量（负载转矩 vs 电机额定）。

**过流/过压（AL.32/33）**

1. 先确认机械没卡死（低速 JOG 试）；
2. 放缓加减速斜坡再试——斜坡太陡是过压/过流的常见推手；
3. 断电测电机线对地/相间绝缘，必要时换线测试；
4. 排因前**不要反复强行上电**——对地短路不处理，再上电就是扩大损坏。

**误差过大（AL.52）**

1. 看滞留脉冲趋势：指令突变时暴涨 = 指令太快/增益低；缓慢爬升 = 正在被堵；
2. 匀速段滞留大 → 调增益/前馈；只有加减速段暴涨 → 放斜坡；
3. 手盘有异响/盘不动 → 机械堵转，先解机械再谈参数。

**再生（AL.30）**

1. 回想是否新加了高频减速工况、缩短了节拍；
2. 量再生电阻的阻值与接线（断线、没接、选小了）；
3. 按手册公式核对再生功率，不够就加/换再生选件。

**过热（AL.45/46）**

1. 监视温度值与趋势，记下环境温度；
2. 查负载率与占空比——长期 80% 以上的选型就是带病运行；
3. 查风扇、散热器积尘、安装间距。

### 复位的三条规矩

1. **先取证后复位**：报警码、历史、波形先落日志，再按复位；
2. **复位是脉冲**，宽度按手册（通常几十 ms），别做成长电平；
3. **分清三类报警**：可直复位（瞬时过载、已冷却）、须断电复位（参数/存储类）、须排因才许复位（过流/对地/编码器硬故障）——复位后一律**低速 JOG 验证**再联机。

### 上位机软件的报警处理设计

- **报警字典**：码 → 等级（警告 / 可复位故障 / 须排因故障）→ 中文含义 → 建议动作，内置在软件里，别让操作工翻手册；
- **处理状态机**：报警中禁止发指令 → 读码记录 → 按等级提示 → 只对"可复位"亮复位按钮 → 复位后等 RD 再放行；
- **历史存档**：报警码 + 时间 + 当时的速度/转矩/位置快照进日志；反复触发的报警做统计找规律（比如总在周一早晨跳——查气源、冷机这类"开工工况"）；
- 深挖用 Drive Recorder / 示波器：报警前后几秒的转矩/速度波形，比猜快十倍。

## 十二、监视项：报警之外，上位机该盯住哪些量

报警是"已经出事了"，监视是"正在变糟"。ALM 亮起来再动手，永远慢一拍——多数报警在爆发前几秒到几周，都会先在监视量上露馅：输出转矩百分比一路爬坡是过载报警（AL.50/51 一族）的前兆，母线电压抬高是再生报警（AL.30）的前兆，停止后滞留脉冲不收敛是误差过大（AL.52）的前兆。上位机握着全时段、全轴的数据流，这是面板和示波器都给不了的视野。本节给三层监视清单：**调试期盯过程、运行期盯趋势、记录层留证据**（监视项名称与单位以《参数篇》《功能篇》的状态显示章节为准，各代际叫法略有出入）。

### 先分好工：毫秒级的归驱动器，秒级以上的归上位机

| 层 | 谁来看 | 能看到什么 | 看不到什么 |
|---|---|---|---|
| 驱动器示波器 / 驱动记录仪 | MR Configurator2 | 微秒级电流/速度/转矩波形，最精细 | 只能抓"配置过的那一段"，错过了就没了 |
| 面板 / 状态显示 | 调试工具实时页 | 此刻的值，随开随看 | 人盯不了三个班，也不留历史 |
| 上位机周期监视 | 你写的程序 | 10~100 ms 一拍、7×24 小时、全轴同时记，趋势与跨轴关联 | 轮询天生滞后 1~2 个通讯周期，微秒级细节够不着 |

口诀：**毫秒级看驱动器，秒级以上看上位机**——别让上位机去干示波器的活，也别指望有人盯面板盯出趋势来。

### 调试期监视清单：盯住"跟得上吗、费多大劲"

试运行阶段四个问题：位置跟得紧不紧、速度稳不稳、电机费不费劲、指令发得对不对——一项对应一个监视量：

| 监视项 | 正常长什么样 | 异常长什么样 | 说明 |
|---|---|---|---|
| 滞留脉冲（偏差计数） | 加减速段有值，停止后收敛进 INP 范围 | 停止后仍大且不动：联轴器松/堵转/增益太低；固定偏差：齿轮比或当量错 | 三环闭环的本质（第三节）；到位判定 INP+滞留双确认（坑 10） |
| 指令位置 vs 实际位置 | 两条曲线形状一致，差值 = 滞留脉冲 | 形状对不上：丢步/打滑/当量错；等距差一截：齿轮比错 | 反馈链就是编码器（第四节） |
| 实际速度 | 稳速段平直、毛刺小 | 毛刺大：机械共振或增益不配（第九节）；忽快忽慢：负载突变或打滑 | 速度环品质的直接体现 |
| 输出转矩（%） | 加减速段冲高、匀速段回落低位 | 匀速段仍高：摩擦/干涉/选型欠账（第五节症状表）；长期顶上限：TLC 常亮的前奏（坑 4） | 转矩是"费劲程度"的体温计 |
| 指令脉冲频率 / 指令值 | 与上位机侧计数值对得上账 | 发了但驱动器没收到：接线/参数/指令源问题——先把锅分清再调驱动器 | 指令通道核对（第六、七节） |

调试期动作建议：**每改一次增益或参数，把这几项的数值/波形存一档**——"改前 vs 改后"有据可查，第九节调谐判定的素材就出自这里。

### 运行期监视清单：盯住"还健康吗、能撑多久"

交付之后，监视的目的从"调好"变成"别坏在产线上"。这层的价值全在**趋势**——单点值没有意义，斜率才有意义：

| 监视项 | 看什么 | 坏消息长什么样 | 关联后果 |
|---|---|---|---|
| 负载率 / 有效转矩趋势 | 同工况下耗力是否越来越费 | 同配方同节拍，负载率逐周上台阶 = 机械在劣化（润滑、张紧、轴承） | 提前换油紧皮带，躲开 AL.50/51（第十一节） |
| 驱动器 / 电机温度 | 热平衡在哪、涨多快 | 环境没变温度爬升 = 散热失效或负载变重 | 温度是过载族报警的直接前哨 |
| 母线电压 / 再生负载率 | 制动能量泄放的余量 | 电压逐月抬高、再生负载率逼近上限 | AL.30 前兆——再生功率账见第五节，排查卡见第十一节 |
| 电池状态（绝对式） | 电压与寿命余量 | 电压低警告 = 是工单不是报警，按计划换 | 耗尽即 AL.25（第四节实操流程一的保养口径） |
| 报警历史 / 累计运行时间 | 什么时候坏、坏了多少次 | 同一报警反复出现 = 系统性问题；单次是偶然 | 统计与复位三分法见第十一节 |

> 运行期监视的本质是**把报警从"突发事件"变成"渐进过程"**：曲线抬头时就保养，比停机抢修便宜一个数量级。

### 记录层：监视数据怎么存才在排障时真有用

监视不落库 = 白监视。按三档设计（周期与容量按上位机资源定）：

- **周期库**：10~100 ms 一拍存当前值（位置、速度、转矩、状态字），按天/周滚动归档——覆盖九成趋势需求，别让它无限膨胀；
- **事件快照**：报警、急停、使能断开等事件发生时，把**前后几秒**的高频缓冲整段存档——第十一节"先取证后动手"要的数据就在这里；
- **变更留痕**：参数修改、齿轮比调整、原点重建，谁在何时把什么从多少改成多少——排障先看"最近谁动过什么"（与第十四节规则 7 日志留痕配套）；
- **微秒级波形不归上位机管**：要电流环/速度环级细节，远程触发驱动器示波器抓一段再取回文件（通道实时性边界见第十节）。

### 阈值三步法：预警线永远抢在报警线前面

1. **测基线**：设备调好后，把典型工况下各监视量的正常波动带记下来（均值 ±3σ 的土办法就够）——这就是健康档案；
2. **设预警线**：基线带外留 20~30% 余量设黄色预警——只提示不动作；
3. **设动作线**：逼近报警阈值处设红色——提示并引导处置（降速、停止派新活），**永远比报警阈值早一步**。

注意：监视值经通讯轮询而来，天生滞后 1~2 个通讯周期（滞后一拍机制见第七节）——**只能拿来做判定与趋势，别回写进控制逻辑**，用旧地图开不了车（第十四节规则 2 的延伸）。

### 监视模块的软件要点（C# 视角）

- **采集与业务解耦**：后台定时轮询、业务只读快照——别在按钮事件里"想起来才读一次"；
- **时间戳用采集时刻**：每条记录带本机单调时钟，多轴曲线才对得齐；
- **断线要可见**：连续超时就标"数据缺失"，**别拿最后一次旧值接着画**——假数据比没数据害人；
- **监视与报警共用一套字典**：监视项、报警码、处置建议同源维护（第十一节报警字典），别两个界面各说各话。

```csharp
// 周期采集骨架（示意）：独立定时器轮询，业务只读最新快照
volatile ServoSnapshot latest = new();               // 各轴最新监视值（字段）
var timer = new System.Timers.Timer(50);             // 50 ms 一拍（10~100 ms 档）
timer.Elapsed += async (_, __) =>
{
    var snap = await comm.ReadMonitorAsync(allAxes); // 一次轮询合并读多个监视项（第十节）
    if (snap is null) { comm.MissStreak++; return; } // 超时：记缺失，不用旧值续画
    comm.MissStreak = 0;
    latest = snap;                                   // 原子替换引用（volatile）
    trendStore.Append(DateTime.UtcNow, snap);        // 周期库 + 滚动归档
};
```

> 口诀：**调试盯跟随，运行盯趋势，事件存快照，改参必留痕；监视线抢在报警前，滞后数据别当控制用。**

## 十三、从零到转起来：上位机侧的完整流程

> 每一步给出"操作 + 放行标准"，**达标才进下一步**；全程填《调试记录》（做了什么、改了哪个参数、现象、结论）。中途报警别硬闯，回第十一节按排查流程走。照单打勾的执行版见《MR-J5 参数与调试清单.md》。

**第 1 步：接线 + 上电——先让硬件"活着"**

操作：

- 断电完成全部接线：主电路电源、控制电源、电机动力线（U/V/W 相序）、编码器 CN2、FG 接地；逐项核对电源等级、电机与驱动器配套（选型四步账见第五节）；
- 编码器线与动力线**分开走线**（第十一节排查卡的惯犯源头）；
- 确认急停、LSP/LSN 限位的硬线真实在位；
- 上电顺序：控制电源 → 主电源；**首次上电脱开负载**（联轴器先不连）。

放行标准：面板显示正常、无任何报警；急停按下/旋起的状态切换正常。

**第 2 步：连接与备份——给自己留后悔药**

操作：

- 电脑连 USB（CN4），打开 MR Configurator2 识别到轴；
- 读固件版本、序列号，与《MR-J5 资料下载与文档清单.md》的核对清单比对版本支持；
- **备份全部参数**，按"日期_轴号_状态"命名存档——这份同时是"出厂参数"，改坏了随时回滚。

放行标准：能识别、能读写，版本受支持，备份文件在手。

**第 3 步：基本设定——把"语言"对上**

操作（第八节参数重点的落地）：

- 在基本设定/向导里填机械信息（导程、减速比），或直接算电子齿轮（公式与例子见第八节）；
- 选控制模式（位置/速度/转矩）与指令源（脉冲/模拟/总线）；
- 加减速先保守，转矩限制先压到 50%；
- 按编码器用法收尾：绝对式接 CN6 电池并完成绝对位置建立（第四节实操流程一）；增量式定好回零方式，第 4 步 JOG 后即可试回零；
- 写入 → 若该组参数要求断电生效就断电重启 → **回读比对**。

放行标准：回读值与写入一致、无 AL.37；换算当量心算能对上。

**第 4 步：JOG 试运行——确认"手脚听指挥"**

操作（用工具自带的试运行页）：

- 速度设额定 10% 左右，先单方向点动：确认旋转方向与上位机定义的 CW/CCW 一致；
- 反方向点动，往返几次：听有无异响、看有无低速爬行；
- **手动触发限位**：确认 LSP/LSN 能让对应方向停住；
- 带抱闸轴：确认"先 SON 后松闸"，松闸瞬间轴不下滑（用第十五节坑 9 的实测法）。

放行标准：方向正确、限位有效、运动平滑无异响。

**第 5 步：自动调谐 + 定位测试——确认"跟得准"**

操作：

- 先做**定标验证**：发"正好 1 圈 / 10 mm"的指令量，核对实际位移（第十五节坑 1 的方法）；
- 按工具提示做自动调谐的小往返运动，读出估测惯量比，与理论值对——差一个数量级就查折算（坑 6）；
- 示波器抓阶跃响应：看超调量、稳定时间、转矩毛刺（判定方法见第九节）；
- 做几个定位点：确认 INP 正常亮、滞留脉冲收敛到位。

放行标准：阶跃响应无持续振荡、INP 可靠动作、惯量比可信。

**第 6 步：联机——把控制权交给上位机**

操作：

- 指令源切到正式通道（总线/脉冲），确认使能状态机走通（EtherCAT 序列见第十节 CiA402 小节，Modbus 见"控制字—状态字"流程）；
- 上位机走"SON → 等 RD → 发指令 → 等 INP"时序，首跑用**低速小行程**；
- 监视滞留脉冲与实际位置跟随，逐级提速、逐级加大行程，每档看一次示波器（监视项清单见第十二节）。

放行标准：低速联机连续运行无报警；重复定位精度（同一点 10 次散差）达标。

**第 7 步：安全验证 + 提速提载——最后才放开手脚**

操作：

- **三测试**：急停（运行中按下，应按设定方式停）、断网（总线型拔线看行为）、断电（抱闸轴看能否抱住）；
- 软限位 + 硬限位都实走验证一遍；
- 提速度、提负载按阶梯来，每档观察转矩 % 趋势与温度趋势；
- 结束后**存最终参数快照**，调试记录归档（第十四节硬规则 7）。

放行标准：三测试全部通过、满速满载连续运行无报警，参数快照与记录归档。

## 十四、写上位机程序的几条硬规则

**规则 1：状态机化——用信号推进，不用延时硬等**

- 反面场景：`Sleep(500) 后发指令`——驱动器主电路充电慢一点（可能 2 秒），指令全丢；快一点则白等浪费节拍；设备状态一变，程序全乱。
- 正确做法：把每个动作建模成状态，迁移条件是**信号**（RD、INP、状态字位），不是时间：

```csharp
// 使能序列的状态机骨架（示意）
switch (state) {
  case WaitReady:  if (rd)               state = SendCmd;   break; // RD 亮才发指令
  case SendCmd:    if (inp)              state = Done;      break; // INP 亮才算到位
  case Any:        if (elapsed > 10s)    state = Error;     break; // 每个状态都要有超时出口
}
```

- 细节：每个状态都配超时出口；状态迁移写日志（复现"卡在哪一步"全靠它）；轮询非阻塞——总线型一个通讯周期查一次就够，别空转占 CPU。

**规则 2：一拍延迟——指令与反馈都有相位差**

- 反面场景：写完目标位置**立刻**读实际位置，判断"没动"于是重发——重复指令、假故障、日志一塌糊涂。
- 原理：循环总线写下的指令下一通讯周期才被从站执行，反馈再滞后一拍（机制见《CC-Link 通讯详解.md》第五节"伺服从站视角"）。
- 做法：所有"写后判断"至少间隔 1~2 个通讯周期；**到位判定以 INP / 状态字为准**，不以"读回来的值对不对"为准；联调文档里画出周期边界，团队共识。

**规则 3：单位集中管理——换算只写一处**

- 反面场景：A 界面按 mm、B 报文按指令单位，两处各自乘系数；后来改了导程或减速比，只改了一处——另一处悄悄错。
- 做法：
  - 全工程只留一个换算入口，例如 `Units.MmToCommand(double mm)`，任何人不得在界面代码里手写系数；
  - 导程/减速比/齿轮比只从**一份配置**读，界面只显示不重复定义；
  - 上电自检做"反算当量"：发 1 圈量位移（第十五节坑 1 的定标验证），与配置不符就**拒绝启动**——把人工排查变成自动拦截。

**规则 4：写后回读——写成功 ≠ 写进去了**

- 反面场景：写帧应答 OK，实际参数没生效（地址错、写了只读区、该参数要断电生效）——到设备上才发现白写。
- 做法：
  - 参数写入统一走 `WriteParamVerify(addr, value)`：写 → 读回 → 比对 → 不一致重试一次 → 仍失败报错停止；
  - 比对的是**驱动器读回的寄存器值**，不是本地变量；
  - "断电生效类"参数：写完明确提示"需重启生效"，重启后自动回读核验一遍。

**规则 5：超时与重试——任何等待都有兜底**

- 反面场景：RS-485 某台偶发无应答，程序死等 → 整条线卡死；或者无脑重试把总线打瘫。
- 做法：
  - 每次事务带超时：`TrySend(frame, timeout: 100ms)`；
  - 重试有上限（1~2 次），失败升级为"通信故障"，进入第十一节的处理状态机；重试之间加一点间隔，别风暴式连发；
  - 轮询预算：单次事务时间 × 站数 < 循环周期，超了就合并读（第十节 Modbus 的"连续地址一次 0x03 读回"）。

**规则 6：安全独立——软件层永远不是最后防线**

- 反面场景：急停做在 PLC/PC 逻辑里，通信一断、程序一死，轴照跑。
- 做法：
  - 硬件链路先行：急停按钮 → EM2/EMG/STO **硬线**、限位 → LSP/LSN 硬线；软件只做**附加**保护（软限位、速度限幅）；
  - 验收按第十三节第 7 步的三测试（急停/断网/断电）逐项过；
  - 软件内部的安全动作也走最短路径：报警即"停发指令 + 撤 SON"，不经过一长串 if 判断。

**规则 7：日志留痕——出事时能"回放现场"**

- 反面场景：客户来电"昨天偶尔报 52"，现场什么数据都没有，只能猜。
- 做法：
  - 三层日志：**事务层**（报文级，默认关、排查通信时开）、**动作层**（状态机迁移：等 RD→发指令→到位，排查逻辑用）、**事件层**（报警码 + 快照，排查工艺用）；
  - 报警快照：报警时刻把指令值、实际值、转矩 %、固件版本一并写入（第十一节的报警处理设计）；
  - 参数快照制度：调试前后、批量改参后自动存档（第十三节第 2、7 步的备份动作）。

### 代码评审自查清单

- [ ] 所有等待挂在信号上，每个状态有超时出口
- [ ] 写后判断预留 1~2 个通讯周期，到位判定用 INP/状态字
- [ ] 单位换算只有一个入口，自检会反算当量
- [ ] 参数写入一律"写 → 读回 → 比对"，断电生效类有明确提示
- [ ] 每条报文有超时，重试有上限，连续失败升级为报警
- [ ] 急停/限位走硬线，软件只做附加保护，断网/断电/急停三测试通过
- [ ] 三层日志齐备，报警带工况快照，参数有快照制度

## 十五、常见坑（上位机视角）

排查总原则（先于一切技巧）：

- **分层定位**：指令到了吗（报文/脉冲）→ 使能链路通吗（SON→RD）→ 参数对吗 → 机械好吗——一层层收窄，别跳步；
- **用数据说话**：MR Configurator2 的监视（滞留脉冲、输出转矩 %、实际位置）和示波器是排查主力，别靠感觉和猜；
- **一次只改一处**：改前备份参数、改完做记录——不然修好了也不知道是哪一步起效。

以下每坑配一段 C# 骨架（✗ 错 / ✓ 对）；类名、参数名按自家封装与所用品牌手册替换。

1. **电子齿轮/单位错** → 走非、疯跑、撞机（第一大坑，没有之一）
   - 排查：空载低速做**定标验证**——发"正好 1 圈"的指令量，监视实际位置是否恰好转 1 圈（顺便分离"换算错"和"机械打滑"）；
   - 核对公式"每转指令脉冲 = 编码器每转脉冲 × 分子 ÷ 分母"，分子分母颠倒是最常见错法；再发 10000 个单位量一下实际位移，反推当前当量与设计值比对；
   - 方向反了先查指令符号/输出相序，别去动齿轮比。

```csharp
// ✗ 系数散落各处——改导程时必漏改
double pulses = mm * 1000;                      // 这个 1000 是谁的当量？

// ✓ 唯一换算入口 + 上电自检反算当量
double pulses = Units.MmToCommand(mm);
Units.VerifyCalibration(mmPerRev: 10.0);        // 发 1 圈量位移，不符拒启动
```

2. **不等 RD 就发指令** → 指令被丢弃，还以为驱动器坏了
   - 排查：先确认程序里发指令前有没有"等 RD"这个条件——没有就是它；
   - RD 一直不亮时查：主电路电压（充电中/欠压）、当前有无报警、EM2/急停链路是否断开，总线型再看状态字对应位；
   - 验证：示波器抓 SON、RD、指令计数三条曲线，看指令是不是落在 RD 之前。

```csharp
// ✗ 睡一觉再发：驱动器慢一点指令全丢
Thread.Sleep(500);
SendMove(target);

// ✓ 等信号，带超时兜底（规则 1）
if (!WaitUntil(() => io.RD, TimeSpan.FromSeconds(5)))
    throw new TimeoutException("RD 未就绪，禁止发指令");
SendMove(target);
```

3. **报警复位做成电平** → 故障被掩盖或复位无效
   - 排查：RES 用**脉冲**（宽度按手册，通常几十 ms 以上），复位后回读报警寄存器确认清零；
   - 清不掉的报警别硬刷——先读报警码判断故障源（过载还没散热、编码器线还断着，刷一百次也没用），并把"复位前报警码"记进日志。

```csharp
// ✗ 电平长按：复位期间新报警被掩盖
io.RES = true;

// ✓ 先取证，再脉冲复位，回读确认清零
LogAlarm(ReadAlarmCode(), Snapshot());
io.RES = true;  Sleep(50);  io.RES = false;
WaitUntil(() => ReadAlarmCode() == 0, TimeSpan.FromSeconds(2));
```

4. **转矩限制没放开** → "电机带不动"，其实是参数在限力
   - 排查：监视 TLC 位和输出转矩 %——**一直贴着限制值**就是在限力；
   - 查正/反两个方向的转矩限制参数，重点查试运行时临时压低的值有没有恢复回来；建议留一份"临时改动恢复清单"。

```csharp
// ✗ 试运行时压低限制，之后忘恢复——现场"带不动"
WriteParam(TRQ_LIMIT_POS, 20);

// ✓ 临时改动走统一作用域：登记 + 自动恢复 + 回读校验
using (TempParam.Scope(TRQ_LIMIT_POS, 20, note: "试运行护机械"))
    Jog(speedPct: 10);
// 离开 using 自动恢复原值并 WriteParamVerify（规则 4）
```

5. **指令源没切对**（脉冲↔总线）→ 写了没反应
   - 排查：先在驱动器侧用 **JOG 试运行**确认机械和使能都正常；
   - JOG 能动、外部指令不动 → 查控制模式与指令输入选择参数（脉冲/模拟量/总线），总线型确认已从脉冲模式切到报文模式；
   - 报文模式仍没反应 → 核对使能状态机有没有走完（位置模式见第十节 CiA402 序列、Modbus 见"控制字—状态字"流程）。

```csharp
// ✗ 直接写报文，没反应还以为驱动器坏了
WriteTargetPosition(pos);

// ✓ 先校验指令源，再走使能状态机（第十节）
EnsureCommandSource(CommandSource.Bus);
RunEnableSequence();                             // CiA402: 0x80→0x06→0x07→0x0F
WriteTargetPosition(pos);
```

6. **惯量比瞎填** → 自动调谐给出的增益不对路
   - 排查：优先用驱动器的**惯量比自动估测**（做几次往返后读估测值），替代手填；
   - 估测值与理论值差一个数量级 → 检查减速比/丝杠/皮带折算有没有漏算、单位有没有填反（折算公式见第五节）；
   - 折算确认后**重新自动调谐**，而不是手改增益硬凑。

```csharp
// ✗ 抄图纸数字填惯量比，和现场机械两码事
WriteParamVerify(INERTIA_RATIO, 3.0);

// ✓ 用驱动器估测值回填，加范围校验
double ratio = Drive.RunInertiaEstimation();
if (ratio is < 0.1 or > 100)
    throw new MachineCheckException("惯量比估测异常，先查减速比/丝杠折算");
WriteParamVerify(INERTIA_RATIO, ratio);
```

7. **软件急停替代硬件急停** → 通信一断就裸奔
   - 排查：做**断网测试**——运行中拔通信线，轴应按设定方式停下；停不下来就说明只有软停；
   - 核对急停按钮到驱动器 EM2/EMG（或 STO）的**硬线**路径真实存在；软件限位只算第二道防线，把"断电/断网/急停三测试"写进验收清单。

```csharp
// ✗ 把"安全"押在通信回调上——线断了它自己也不跑了
Bus.OnCommunicationLost += (s, e) => StopMotor();

// ✓ 硬线链路独立存在，软件只做附加保护（规则 6）
SafetyChain.RequireHardwareEStop();              // 启动自检：硬线不在位拒运行
SafetyChain.RequireHardwareLimits();             // LSP/LSN 硬线检查
```

8. **增益从别的机器照抄** → 这台振那台爬
   - 排查：恢复默认/出厂增益 → 重新自动调谐，让这台的机械自己说话；
   - 用示波器抓阶跃响应，按"超调量/稳定时间"调，不按"别人家参数"调；出现共振就按第九节"FFT 找峰 → 陷波 → 再升增益"流程走。

```csharp
// ✗ 从老机器整包导参数灌进来
CopyAllParamsFrom(otherMachine);

// ✓ 这台现场重新调谐，用响应指标验收放行
Drive.RunAutoTuning();
var r = Scope.CaptureStepResponse();
Verify(r.OvershootPct < 5 && r.SettlingMs < 30); // 不达标不放行
```

9. **抱闸时序错** → 竖轴掉刀、划伤工件
   - 排查：监视 MBR 与 RD/ZSP 的先后关系——**先有保持力，后松闸**；
   - 实测：松闸瞬间盯实际位置，若下滑则加大"伺服 ON → 松闸"的延迟参数；停机顺序核对为"减速到零速 → 抱闸 → 再断 SON"；
   - 别忘了验证**断电/急停瞬间**的抱闸动作——竖轴最怕的就是这个时刻。

```csharp
// ✗ SON 和松闸同一拍——竖轴瞬间下滑
io.SON = true;  io.MBR = true;

// ✓ SON → 等有保持力 → 延时松闸；停机走反向顺序
io.SON = true;
WaitUntil(() => io.RD, TimeSpan.FromSeconds(2));
Sleep(brakeDelayMs);                             // 对应驱动器抱闸时序参数/受控 DO
io.MBR = true;
// 停机：减速到 ZSP → io.MBR = false（抱闸）→ io.SON = false
```

10. **INP 设太宽** → 到位判定虚，下一步动作提前抢跑
    - 排查：停止后监视**滞留脉冲的稳定值**——INP 阈值要卡在"大于它、小于工艺允差"之间，两头定出来；
    - 示波器看到位后滞留脉冲的收敛过程，确认能真正落进阈值；
    - 实测重复定位精度（同一点走 10 次记散差），用数据定 INP，不拍脑袋。

```csharp
// ✗ INP 阈值拍脑袋——到位判定虚
WriteParamVerify(INP_RANGE, 1000);

// ✓ 阈值卡两头：停止后实测滞留 < INP < 工艺允差
double settled = MeasureDroopAtStandstill();
double allowed = Units.MmToCommand(processTolMm);
WriteParamVerify(INP_RANGE, (int)((settled + allowed) / 2));
VerifyRepeatability(cycles: 10);                 // 同点 10 次散差实测
```
